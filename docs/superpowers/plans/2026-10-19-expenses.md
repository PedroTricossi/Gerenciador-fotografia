# Expenses Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pedro records his expenses: one-off ones (with trip details for transport), monthly fixed costs and the second photographer's fee per wedding. He sees them month by month on a Despesas tab of the Negócio page.

**Architecture:**
- **Backend:**
  - A pure `domain/expenses.py` holds the month, price-history and occurrence rules.
  - New tables (Alembic `0005`) hold expense types, manual expenses, fixed costs with their price history, the standard second-photographer fee history, and per-contract fee overrides.
  - Fixed-cost occurrences and automatic fees are **derived** when read, never stored per month.
  - The services are `ExpenseTypeService`, `ExpenseService`, `FixedCostService` and `SecondPhotographerService`. An `ExpenseEntryService` merges manual, fixed and automatic entries for a month range: the read path for the Despesas tab and for piece 3.
- **Frontend:** the Negócio page gets Parcelas/Despesas tabs. The Despesas tab has month navigation, the entry list, a Configurações box, and dialogs for an expense, the fixed costs, the fees and the types, all built from existing `ui/` components.

**Tech Stack:**
- Backend: Python 3.13, FastAPI, SQLAlchemy 2.0, Alembic, pytest.
- Frontend: React 19, TypeScript, TanStack Query, React Hook Form, Vitest, MSW.
- End to end: Playwright with axe.

**Spec:** `docs/superpowers/specs/2026-10-19-expenses-design.md`

## Global Constraints

**Values**
- **Money:** integer centavos, using the existing `Cents` (`gt=0, le=100_000_000`) for every amount.
- **Distance:** integer tenths of a km, from 1 to 50 000 (0,1–5000 km).
- **Months:** `"YYYY-MM"`, validated with the same pattern as `InstalmentIn.month`.
- **Times:** `HH:MM`.

**Types**
- Seeded by the migration, in this order:
  1. Transporte (`key="transport"`)
  2. Equipamento
  3. Café
  4. Assinatura
  5. 2º fotógrafo (`key="second_photographer"`)
  6. Outro
- Other types have `key=None`.
- Names are 1–60 characters, unique among active types ignoring case, the same rule as `CatalogService._check_name_free`.
- Keyed types can be renamed but not archived (409).

**Event links**
- Stored as `contract_id` + `event_kind` (`"wedding"` | `"prewedding"`), never the pre-wedding row id.
- Allowed only on a type with `key="transport"`.
- New links need an active contract and, for `prewedding`, an existing pre-wedding row. A link already stored may stay dangling.
- **Trip fields:**
  - `transport_kind` is one of `car`, `ride_app`, `bus`, `plane` or `other`, shown as Carro, App (Uber/99), Ônibus, Avião and Outro.
  - Also `left_home_at` and `distance_tenths`.
  - All are required when linked and null when unlinked. Changing the type away from transport clears the link and the trip fields.

**Fixed costs**
- Name: 1–100 characters. Day: 1–31, clamped to the month's last day.
- `start_month` ≤ `end_month` when an end is set. A price's `from_month` is ≥ `start_month`.
- The first price's `from_month` is `start_month`.
- Setting a price on a month that already has one replaces that entry.
- The type is any active type except `key="second_photographer"`.

**Second-photographer fee**
- **Standard history:** entries are `(from_month, amount_cents)`, unique by month, and setting a month again replaces its entry.
- **Which weddings:** every non-deleted contract with `photographer_count >= 2` has one entry, dated on `event_date`.
- **Amount:** the override if one exists, otherwise the standard in force that month. If neither exists, the amount is 0 with `missing_amount=true`.
- **Overrides:** an override needs an active contract with `photographer_count >= 2` (409 otherwise). Clearing one is always allowed.

**Read path**
- `GET /api/v1/expense-entries?from=YYYY-MM&to=YYYY-MM`. The range is inclusive, at most 24 months, and `from` ≤ `to` (422 otherwise).
- Results are ordered by date, then source order `fixed`, `manual`, `second_photographer`, then `created_at`, then id.
- Stable ids:
  - `manual:<expense id>`
  - `fixed:<fixed cost id>:<YYYY-MM>`
  - `fee:<contract id>`

**Audit**
- Actions:
  - `expense_type.created`, `expense_type.updated`, `expense_type.archived`, `expense_type.restored`
  - `expense.created`, `expense.updated`, `expense.deleted`
  - `fixed_cost.created`, `fixed_cost.renamed`, `fixed_cost.price_set`, `fixed_cost.stopped`, `fixed_cost.resumed`, `fixed_cost.deleted`
  - `second_photographer_fee.set`
  - `second_photographer_override.set`, `second_photographer_override.cleared` (entity `contract`)
- Details hold only `version`, `fields` (names), `month`/`from_month`/`end_month`, and ids.
- They never hold amounts, names, descriptions, addresses or distances.

**Portuguese UI text**
- Tabs "Parcelas" and "Despesas" (SegmentedControl label "Área"). The tab is kept in the URL as `?aba=despesas`, and the default is Parcelas.
- Buttons and dialogs: "+ Nova despesa", "Editar", "Ajustar", "Gerenciar", "Alterar", "Tipos de despesa", "Parar", "Retomar", "Excluir", "Salvar", "Cancelar".
- Tags "fixa", "automática", "prevista". "Total de <mês>: R$ x". Empty state "Nenhuma despesa neste mês."
- Fee rows: "2º fotógrafo · <casal>", or "2º fotógrafo · <casal> — sem valor" when the amount is missing.
- Dangling links: "(contrato excluído)" and "(pré-wedding cancelado)".
- Description hint: "Não escreva CPF ou endereço aqui."

**Project rules**
- All existing rules hold:
  - layered backend, RFC 9457 problems, Origin/JSON checks on writes, `If-Match` on PATCH/DELETE of versioned rows;
  - never name a method `list`, and migrations copy their helpers instead of importing app code;
  - the `ui/` layer with tokens only and feature CSS for layout only;
  - WCAG 2.2 AA, CSP `default-src 'self'`;
  - tests that query by role, label and text;
  - no edits to existing tests unless a task step names them.
- "Today" and "current month" are the browser's local date in the UI. The server never decides "prevista".

## Review Focus

1. **A fixed cost on day 31 across February (leap and non-leap) and 30-day months**, and a backdated price entry. Past months before the entry keep their amount, and months from it on change. Tests in Task 1 and Task 5.
2. **A wedding's date moving across months, its photographer count dropping to 1, and delete then restore:** the fee entry follows each time, and the override survives a restore. Tests in Task 6.
3. **A transport expense whose pre-wedding is cancelled or whose contract is deleted:** it still lists in its month with the dangling label, no venue, no 500, and it can still be edited and saved. Tests in Tasks 4 and 6.
4. **Double-submitting the expense form or a price change:** one row or entry results, and stale `If-Match` gives the existing 412/409 handling. Tests in Tasks 4 and 8.
5. **Amounts typed with a comma ("86,50") and distances "32,5" or "32":** they parse to 8650 and 325/320, and "32,55", "0" and "5000,1" are refused with a field message. Tests in Task 7.
